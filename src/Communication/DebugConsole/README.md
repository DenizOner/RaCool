# CLI and Developer Tools

`HELP` lists product commands. `DEVELOPER` or `DEVELOPER STATUS` reads the preference; `DEVELOPER ON` enables the tools and `DEVELOPER OFF` closes them. `DEVELOPER STATUS --machine` returns `RACOOL_CLI v=1 type=developer_mode enabled=0|1`. The configuration owner persists the preference before applying it; the factory default is OFF and the saved value survives restart. It is a usability boundary, not authentication.

An ON/OFF change fails without altering the mode if the system configuration block has unsaved edits, so the preference cannot implicitly commit unrelated settings. Resolve those edits through their owner before changing the preference.

While enabled, use `DEVELOPER TOOLS` or `HELP developer` to list tools, or `DEVELOPER TOOLS logging`, `diagnostics`, `hardware`, `protocols` or `metrics` to inspect a group. `HELP <category>` also works while enabled. The list distinguishes read-only routes from commands that may change state; mixed commands appear with their specific subcommands. Execute the listed command as shown. Product commands continue to work in both modes.

`DeveloperMode.c` uses the ESP-IDF console tokenizer to classify individual command paths, including mixed product/developer roots. Temporary token storage is cleared. Unlisted roots and paths require Developer Mode. When adding or changing a command, review its actual function, help, completion, machine consumers and side effects, update this policy and cover both modes. `SYSTEM CONFIG SET` and `SYSTEM CONFIG XY` are product settings; the complete configuration snapshot is a developer view. `ZB RESET CONFIRM`, `config.reset [block] CONFIRM` and `LOGS clear CONFIRM` require explicit confirmation tokens and are developer-only.

The serial diagnostic helper `test/Communication/DebugConsole/diagnostic/developer_session.py` reads the original mode, enables it only if necessary, verifies readback and restores only its own change. After observing a real reboot and registered console, call `after_boot()` before developer commands. Its exchange callback must send once, wait for a bounded fresh complete response and avoid replay after uncertain delivery. `serial_capture.py --developer` uses this session for developer command captures. Inspect each live helper's own baseline, ownership and restoration contract before running it; mode admission does not authorize changes to device settings.
